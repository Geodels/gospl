# Fixed bugs (regression-guarded)

Each entry: the symptom, the root cause, the fix and the guard test that fails without
it. Moved out of `AGENTS.md` (2026-10). The lessons that generalise are summarised in
the root `AGENTS.md`; read the full entry here before touching the code it names.
Test names below are still valid; their modules changed in the 2026-10 test split
(`tests/test_regression.py` → `tests/test_<subsystem>.py`, see `tests/README.md`).

- **IIOE2 advection (`advect: 'iioe2'`) zeroed any no-overshoot field** — fixed 2026-06-29 in `mesher/tectonics.py` (`_advectorIIOE2`). The global overshoot magnitude was reduced into `self.tmp` — the same Vec that held the Scheme-1 advected field — so when the global `excess == 0` (no overshoot; the *common* well-behaved case for a monotone Scheme-1 result) the anti-diffusion branch was skipped and `_advectField` copied the all-zero `diff` left in `self.tmp` back into the field. Elevation (and cumED/flexure/soil) flattened to exactly 0 on the first advection step (reported on `Local-examples/stratigraphic_record/input-advect.yml`). Fix: reduce the excess into `self.tmp1`, leaving the Scheme-1 result in `self.tmp` intact for the no-overshoot path (the `excess > 0` branch overwrites `self.tmp` with the corrected solve anyway). `iioe1`/`upwind` were never affected (no Scheme-2 correction). The pre-existing `test_advection_parallel` missed it because it advects a sharp RIDGE, which always overshoots (`excess > 0`) → the correction always ran. Guard: `test_advection_iioe2_smooth_field_not_zeroed` (advects a **uniform** field → `excess == 0` deterministically; red without the fix; serial + np=8 both verified). **Lesson: a scratch Vec that holds a result-to-keep must not be reused for an intermediate reduction on the skip path.**
- **closed-sink deposition needled open-domain stray sinks (km-scale spike → soil SNES stall)** — fixed 2026-06-24 in `sedplex` (gated on the new `self._domainHasOutlet`). PR #473's `_closedDepo` closure (deposit sediment reaching a flow-terminal node that is `lsink & pitID<0`) was added for WALL domains, but it also fired on OPEN domains: a near-flat shallow low pocket (e.g. 8 nodes at z=273.05–273.96 m hugging the east edge of the `glacial_erosion/input-river-soil.yml` mesh) that the flat-routing couldn't connect to its adjacent edge outlet became a stray sink, and ALL the cascade sediment routed to it was deposited on that single node → a ~9 km needle in step 1 → enormous local gradient → the non-linear soil SNES stalled (500 wasted primary iters, failover to the fallback). Fix: `_closedDepo` deposits in place ONLY when the domain has **no drainable outlet** (`_domainHasOutlet = allreduce(len(outletIDs)>0, LOR)` is False — a global sphere with no borders, or an all-wall box), to conserve mass as #473 intended; on an OPEN domain the stray-sink sediment instead **leaves the domain** (discarded — it would have drained to the boundary), so no needle. Sphere `test_mass_conservation` and all-wall `test_wall_boundary_conservation` are unchanged (both have no outlet → still deposit). The deeper cause — flat-routing not connecting a near-flat low pocket to an adjacent boundary outlet — is the documented hard flat-terrain problem and is NOT fixed here (tracked separately); C just stops the unphysical needle. Guard: `test_closed_sink_deposition_scope` (`_domainHasOutlet` True on open `incising`, False on `flat_wall` + sphere `minimal`).
- **np>1 flow-KSP deadlock: collective `Vec.norm`/`Mat.norm` gated on `MPIrank==0`** — fixed 2026-06-24 in `flowplex._solve_KSP2`. The divergence diagnostic computed `rhs_finite = np.isfinite(vector1.norm())` and `mat_finite = np.isfinite(matrix.norm(...))` **inside `if MPIrank == 0:`**. `Vec.norm`/`Mat.norm` are **collective** (`MatNorm_MPIAIJ` → `MPI_Allreduce`), so only rank 0 entered the `Allreduce` → it blocked forever waiting for ranks that skipped it, while those ranks marched on to the next collective (`garbage_cleanup`'s `Allreduce`) → desync → **hang** (and the `GarbageKeyAllReduceIntersect` `MPI_ERR_BUFFER` crash some users saw was a *downstream symptom* of this desync, not the cause). It only fired when a flow solve diverged with a **non-benign** un-drained region (`nbad > _undrained_benign_cap`) — e.g. the near-flat `implicit_timestepping` plateau under uniform uplift (~636 ponding cells). (The cap was a fixed 256 at the time and the loud branch ran; it is now `max(256, 0.5%·mpoints)` — relative to mesh size — so that flat-terrain ponding is reported calmly. Either way the *deadlock* was the rank-0-gated collective, not the threshold.) At np=1 the "collective" norm is local, so **serial always worked** — the classic serial-passes/parallel-hangs signature. Fix: compute the norms on **every** rank (guarded only by the rank-consistent `benign` flag), print only on rank 0. The `implicit_timestepping/input-5k.yml` (290k, `bc='oooo'`) now **completes** at np=2 (20 steps, ~65 s) instead of hanging. **Lesson (recurring): any `Vec`/`Mat` reduction, `localToGlobal`, or `Allreduce` placed under `if MPIrank == 0`/a rank-local `.any()` deadlocks np>1 — keep the collective on all ranks, gate only the print/IO.** This is the same bug class as the coastline-rebuild and closed-sink-deposit deadlocks. Guarded by `test_mpi_abort_on_exception` (clean-abort backstop) + the full suite at np=2.
- **parallel hang on any uncaught exception → clean `MPI_Abort`** — added 2026-06-24 in `model.py` (`_install_mpi_abort_excepthook`, installed in `Model.__init__`, np>1 only). Any uncaught exception on any rank now prints the traceback then `MPI.COMM_WORLD.Abort(1)`, killing the whole job — instead of one rank dying while the others block in a collective (the "must kill it manually" hang). Complements the root fix above: a genuinely fatal error (e.g. the `fatal=True` flow solve raising) now terminates ALL ranks cleanly and fast. Guard: `test_mpi_abort_on_exception` (rank-0 raises post-init while rank 1 sits in a Barrier; asserts the job aborts in <90 s, non-zero exit, rank 1 never passes the barrier). Related: `tools/petscgc.py:safe_garbage_cleanup()` routes all 17 `petsc4py.PETSc.garbage_cleanup()` calls through a wrapper that, **on the PETSc-3.21.x collective-GC failure, aborts cleanly** (the failure is an asymmetric collective desync that would otherwise deadlock — swallowing it is unsafe). With the root fix the GC failure no longer occurs; the wrapper is a defensive backstop.
- **orographic `wind_dir` North/South sign (inconsistent "comes from" vs "goes toward")** — fixed 2026-06-24 in `tools/addprocess.py` (wind vector now in one place, `_windVector`). `wind_dir` is documented as the meteorological bearing the wind COMES FROM (0=N, 90=E, 180=S, 270=W), so it blows toward `dir+180`: `(u_east, v_north) = speed·(-sin dir, -cos dir)`. The code had `u = -sin` (correct, "comes from") but `v = +cos` (a "goes toward" North sign) — internally inconsistent. Invisible on E/W winds (`cos` of 90/270 = 0) and on the rain-shadow fixture (`wind_dir=270`), so it never failed CI, but a northerly (`wind_dir=0`) blew toward the **North** instead of the South. Fix: `v = -cos`. The fixture/`test_orography_rain_shadow` (270 → blows East, lee on East) is unaffected (validated the E/W axis all along). Guard: `test_orography_wind_direction_convention` (all four cardinals via `_windVector`). Docs (`optfile1.rst`) already said "comes from"; clarified with blow-toward examples.
- **global (spherical) varying-Te flexure: spurious threaded-BLAS matmul warnings** — fixed 2026-06-24 in `tools/addprocess.py` (`_cmptFlexGlobal`, the `shflex` varying-Te Anderson step; rank-0-only, serial pyshtools). The Anderson type-II least-squares matmuls emitted `RuntimeWarning: divide by zero / overflow / invalid value encountered in matmul` at np>1 (never in a serial run). **The warnings are SPURIOUS**: instrumentation showed the inputs are tiny and finite (`|dG|~36`, `|w|~540` m) and the solve converges normally (`rel` 0.21→<5e-4) — under MPI / threaded OpenBLAS the SIMD GEMM kernels raise FP-exception flags on the tail lanes even for well-formed small inputs, and numpy reports them although the RESULT is correct. (An earlier attempt formed the normal equations `dGᵀdG` with a Tikhonov ridge — that was the wrong call: it *squares* the dynamic range and made the warnings worse, since there was never a real overflow.) Fix: wrap the Anderson matmuls in `np.errstate(divide/over/invalid="ignore")`, use `np.linalg.lstsq(dG_flat, …, rcond=1e-8)` (SVD, no normal-equations squaring; `rcond` bounds `gamma` if the residual history ever does go collinear), and finite-guard the correction (fall back to a plain Picard step if non-finite). **Path-only — converged deflection unchanged.** Validated on `Global-examples/erodep_1My/input-mardep.yml` at np=4: warnings gone, converges. No unit guard (the `minimal` sphere converges in 1–2 iters, never reaching the Anderson block; the warnings need threaded BLAS at np>1 — brittle to reproduce in a fixture).
- **open ('o') boundary deposition runaway on an aggrading downstream edge** — fixed 2026-06-24 in `mesher/unstructuredmesh.py` (`_drainOpenEdges`, replacing the inline `applyForces` open-edge block). Historically an open edge was reset every step to the neighbour **average** (`getbc`, later `fitedges` on a `MISSING_DATA_SENTINEL` mark) — a "smooth" boundary that tracks the interior in BOTH directions. Fine on a steady/incising edge, but on an **aggrading downstream** edge (e.g. the low plain of an escarpment-retreat model, where all eroded sediment drains *toward* the open edge) the average rises with the aggrading plain, the edge loses base-level control, the outward drainage gradient vanishes, and sediment ponds just inside the edge → a **closed-sink deposition runaway** (a node just inside the edge goes `FA=0` and dumps the whole sediment flux: tens-of-km spurious peaks, observed growing to 120 km). It only bit because the NESW bc rework re-pointed a user's `'fooo'` from S=fixed (old `[S,E,N,W]`) to **S=open** (new `[N,E,S,W]`); fixed edges were always stable. Fix: each open node is set to `min(current elevation, min(interior neighbours))` — a per-node running minimum. The `min`-of-neighbours candidate keeps the edge from being a barrier (and is partition-invariant, order-independent); the `min`-with-current makes it **non-rising** — it follows incision/subsidence DOWN but aggradation can never raise it (open edge nodes never erode/deposit — `E`/`fDep` are zeroed on `outletIDs` — so their stored value IS the previous base level; tectonic uplift still propagates because it raises the stored value in `applyTectonics` before this reset). A plain `min`-of-neighbours alone only DELAYS the runaway (the whole near-edge band aggrades and the neighbour-min rises with it); the running-min is the actual cure. This also gives 'o' a stable distinct meaning vs 'f': open is a low free-outflow base level the domain can incise toward but cannot aggrade away; fixed holds its prescribed natural per-node elevation. Validated on the escarpment model (50 Myr, S=open: global zmax 1005→1097 m over 10 Myr vs 4597→121528 m broken; matches the S=fixed run). Guard: `test_open_edge_non_rising` (pins both the non-rising-under-aggradation and tracks-down-under-incision properties on the all-open `incising` fixture; fast + deterministic — the full runaway is mesh-resolution dependent). `fitedges` is now unused in `unstructuredmesh.py` (import dropped; the kernel stays — still used by `tectonics._resetEdges`).
- **continental-sediment closed-sink deposit deadlock at np>1** — fixed 2026-06 in `sedplex._distributeSediment`. The closed-sink conservation closure (`if self._closedDepo.any():`, deposits cascade sediment that reached a closed flow-terminal node) wrapped **collective** DM scatters (`localToGlobal`/`globalToLocal`) inside a **rank-local** `.any()` guard. A closed terminal node (interior, pit-less, above sea, not an outlet) can exist on one partition and not another even on an **open** `'oooo'` domain, so at np>1 one rank entered the scatters while the other skipped ahead to `_updateSinks` → `_spillCoords`'s `Allreduce` — different collectives, permanent deadlock (both ranks 100% CPU). Same bug class as the coastline-gated `_smoothMat`/`_hillMat` rebuild deadlock (see the "collective rebuild decision" rule above): **any collective gated on a rank-local condition needs the reduce.** Guard: `test_advection_parallel` (mpirun -n 1 vs -n 2 on `flat_advect.yml`; previously timed out at 600s, now ~13s).

- **Marine sediment leak at terminal ocean sinks** — fixed 2026-06 at `seaplex._distOcean`. `_matOcean` constructs `dMat1` with a zero column at every terminal sink (cells whose every flow direction is self-referential, typically deep-ocean basin floors); the first `dMat1.mult` therefore annihilated any `sedflux` that landed directly at a sink. `vSed` upstream-integration naturally accumulates large flux at these sinks, so this was the dominant mass-loss path. - **Marine diffusion created sediment on steep bathymetry (asymmetric `ndepo<0` clamp)** — fixed 2026-08-11 in `sed/hillslope.py` (`_diffuseOcean`). The marine sediment diffusion (`_diffuseImplicit` / `_diffuseImplicitPicard`) solves `∂h/∂t = ∇·(Cd∇h)` on the **absolute** seafloor `bed + dh` and then clamps its increment `ndepo[ndepo < 0] = 0` (a fresh deposit cannot erode the pre-existing bed). The solve itself conserves volume over the no-flux marine domain, but where deposits sit on **steep** relief (deep-ocean basin flanks) the smoothing moves large *bed-driven* flux — filling lows, cutting highs — and the `>= 0` clamp keeps the fill while discarding the paired cut, so `Σ ndepo` exceeds the input `Σ dh` (measured ~5–8× inflation → net cumED **+1.6e15 m³, i.e. more deposited than eroded**, on a 10 km real-Earth run). The continental large-pit path never exposed this because `sedplex._diffuseLargePit` rescales each pit's diffused deposit back to its incoming volume (see `docs/tech_guide/dep.rst` "A final per-pit mass rescale absorbs any boundary drift introduced by the diffusion"); the marine path had **no** rescale. Fix: after the clamp, rescale the `(>= 0)` marine deposit so `Σ(ndepo·larea) == Σ(dh·larea)` — a single global factor over the owned marine cells (collective `allreduce` on **all** ranks; provenance sub-thicknesses scaled by the same factor so `Σ_c == total`). It is a **no-op** once deposits sit on gentle slopes (the clamp then discards ~nothing), so well-behaved runs are unperturbed (full suite unchanged, 160 pass). Known limitation: the rescale is **global over the marine domain**, so with multiple *disconnected* seas of differing clamp deficit it can shift a little volume between basins; a per-connected-basin rescale (like `_diffuseLargePit`'s per-pit) would be exact — fine for the single-ocean case, revisit if multi-basin runs need it. NOTE: this fixes the deposited *volume* only; **where** marine sediment lands (bottom-up in the deep ocean vs coastal clinoforms) is a separate concern governed by `oFill` (raise it above the deepest ocean to exclude the abyss from the sediment pit-fill — `fillElevation`'s `sed=True` path skips the `if not sed:` sub-sea clip) and `clinSlp` (the clinoform envelope), NOT by this rescale. Guard: `test_marine_diffusion_conserves_on_steep_bathymetry` (drives `_diffuseOcean` with a thin deposit on the minimal mesh's natural **steep** bathymetry + strong `nlK`/`dt`; pre-fix inflates ~2×, post-fix conserves to < 1e-6). `test_mass_conservation` on the near-flat minimal fixture did NOT catch it (tiny `nlK`/`dt`, gentle relief where deposits land → clamp deficit under the 1e-4 budget). **Lesson: a diffusion that acts on absolute elevation but clamps its increment to one sign is not conservative on relief — rescale the increment to the input volume (as the pit path does), don't just clamp.**
- **Fatal flow-accumulation solve aborted a long run over a knife-edge un-drained region** — fixed 2026-08-12 in `flow/flowplex.py` (`_solve_KSP2`). The fatal main discharge solve (`fatal=True`) used to `raise` on ANY non-convergence. On a large evolving global run (4.25M nodes, 192 ranks) it aborted at 855 kyr of a 1 Myr run: `(I−Wᵀ)` went locally singular over **210 cells** (`nbad=210` ≪ the benign cap `≈21000`; RHS/matrix finite → not a NaN, a genuine null-space blow-up), residual 7e8. The cause was a **near-flat region whose MFD receiver tie-break formed a near-cycle** — a floating-point knife-edge: **restarting from the (float32) output made it vanish with AND without the evaporation module** (the ~1e-7 float32 elevation truncation perturbs the tie-break away; a different rank count would too), which ruled out evaporation and any robust topographic feature. Aborting a 55-min run over ~O(100) knife-edge cells that a restart trivially dodges is disproportionate. Fix: for the fatal solve, if the region is **small and finite** (`0 ≤ nbad ≤ _undrained_benign_cap`, `rhs_finite`, `mat_finite`, localizable), **pond** those cells (discharge → local runoff `b`; plus a clamp of any cell whose discharge exceeds the total domain runoff `Σb`, a hard physical bound that catches the self-consistent-but-inflated cycle interior the residual mask misses) and **keep the converged discharge on every other cell**, then continue — exactly the benign-pond semantics the non-fatal path already uses, now extended to the main solve. Still **aborts** on a large region (`nbad > cap`), a non-finite RHS/matrix, or an un-localizable failure. `nbad`/`rhs_finite`/`mat_finite`/cap are all global and `fatal` is a shared arg, so the pond-vs-abort branch is identical on every rank (collective-consistent, no np>1 deadlock). The bad-cell mask is captured from the residual localization (`bad_mask_local`) that was already computed for the diagnostic. Guard: `test_fatal_flow_solve_ponds_small_undrained_region` (drives `_solve_KSP2(fatal=True)` with a standalone singular 2-cycle matrix: a small region ponds-and-continues with discharge clamped ≤ `Σb`; a `> cap` region still raises). **Lesson: a fatal solve should distinguish a genuinely broken state (large / non-finite → abort) from a knife-edge local singularity (small / finite → pond the pocket and continue); the physical upper bound `discharge ≤ Σb` is the robust clamp for a drainage null-space blow-up.**
- **`oFill` meant two different things (marine eps-fill skipped on a non-zero sea level)** — fixed 2026-08-22 in `sed/seaplex.py` (`_matOcean`). `pitfilling.fillElevation`/`fillIceElevation` compute the depression-fill cut-off as `max(minh, self.sealevel + self.oFill)` (`oFill` = a depth BELOW SEA LEVEL), but `_matOcean` compared the raw `self.oFill` as an ABSOLUTE elevation. Identical when the sea level is 0 — which is every fixture, benchmark and Earth example, so nothing ever caught it — and off by `sealevel` otherwise. It matters because **`epsfill` only eps-fills the cells AT OR ABOVE its cut-off**: the seeding loop pre-flags every cell below `sl`, so the flood never revisits them and they keep their raw (smoothed) elevation. A cut-off placed above sea level therefore skips the ENTIRE marine domain, every closed bathymetric pocket on the shelf survives into the marine flow-direction surface, and river sediment is trapped at the coast instead of routing basinward. Surfaced on a Mars run (`sea: position: -2200` with `oFill: -1500`): the absolute reading gave a cut-off of **-1500 m, i.e. 700 m ABOVE sea level**. Fix: `minh = max(minh, self.sealevel + self.oFill)`, and `_matOcean` records the value as `self._oceanFillLevel` so the contract is assertable. Docs (`user_guide/surfproc.rst`) also stated the absolute reading and were corrected. Guard: `test_ofill_is_relative_to_sea_level`. **Lesson: one YAML key must have one meaning — when the same parameter is consumed at more than one site, compute the derived quantity the same way (or once, in a shared helper).**
- **Declaring `domain: radius` far from the input-mesh radius hung the run on rank 0** — fixed 2026-08-22 in `tools/addprocess.py` (`_buildDHGrid`). The Driscoll-Healy flexure grid was placed on a sphere of `self.radius` and then matched to the mesh with `cKDTree(self.mCoords).query(gridXYZ, k=rgrd_interp)`. That grid exists ONLY to supply directions for the mesh↔grid interpolation, so its radius must be the **mesh's** radius: if the two shells differ, every query point sits a constant radial offset from the whole mesh, all `k` neighbour distances go near-degenerate and the KD-tree loses all pruning. Measured on a 5.9M-node mesh with a Mars `radius: 3389500` declared against an Earth-radius (6371 km) mesh: the 1.04M-point grid query went from **~2 s to ~15400 s (~4.3 h)**. Because `_buildDHGrid` runs **rank-0 only inside `Model.__init__`** while every other rank waits at the next collective, it presents as a **hang during initialisation**, not as a slow step (a 192-rank job just burns its walltime). Secondary correctness effect: the IDW weights `1/d²` flatten to near-uniform, degrading the interpolation to a plain k-point average. Fix: place the grid at `mean(|mCoords|)` and keep the declared `radius` only where it is physical — the elastic-operator eigenvalues `dh_P_l ∝ 1/radius**4`; plus a rank-0 warning when the two disagree by >1%. NOTE the neighbour IDs are NOT affected (squared distance to a concentric shell is monotonic in angle, so the k-NN set and order survive any radial offset) — do not write a guard on `dhIDs`. **`domain: radius` does NOT rescale the mesh:** all geometry (`larea`, edge lengths, drainage areas) comes from the mesh coordinates via `definetin`, so a Mars model needs the MESH rebuilt at the Mars radius; `radius`/`gravity` only enter flexure. Guard: `test_dh_flexure_grid_placed_at_mesh_radius`.

- **`globalngbhs` wrote past the 12-slot global neighbour table on a high-degree mesh** — fixed 2026-09-22 in `fortran/functions.F90` (+ `functions.pyf`, `mesher/unstructuredmesh.py`). ## Test tolerance notes

- **Platform-dependent KSP-noise floor in `test_parallel_correctness`**. With the `gid` exact-tie-break in place, the remaining sum-FA drift between n=1 and n=2 is dominated by KSP-solver floating-point non-determinism at partition boundaries — and the magnitude differs by platform. Measured on `tests/fixtures/minimal.yml`: macOS-14 (arm64, conda-forge OpenMPI) ≈ **0.3%**, ubuntu-latest (x86_64, conda-forge MPICH) ≈ **1.7%**. Same fixture, same goSPL, same Python — the spread is driven by MPI implementation, BLAS variant, and FMA availability at the platform level. The test tolerance for `rel_sum_fa` is set at **5e-2** (5%) to clear both with headroom; a real routing regression would shift it toward 0.5+, not 0.05.
